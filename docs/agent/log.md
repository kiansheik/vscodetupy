## 2026-09-16 (third follow-up)

- The "correct ground truth" hand-off previously tried to auto-open and auto-submit VS Code chat (`workbench.action.chat.open`/`.submit`, with a ChatGPT-panel fallback); the user didn't want that — they want to paste the prompt wherever they choose. Removed all of it: `startCorrection` now always copies the prompt to the clipboard and shows an info message. Also dropped `ignoreFocusOut: true` from both input boxes so clicking away cancels them (Escape already did).
- Added a per-line **"Commit ground truth"** action (CodeLens + editor right-click) that lets the human approve an already-correct rendering directly, without going through the AI-chat correction flow: `tupy.commitGroundTruthLine` confirms once, saves the document if dirty, and calls the sibling repo's new `authoring.service.commit_ground_truth(source, ordinal)` through `scripts/commit_ground_truth.py`. It only ever writes the JSONL record for that one ordinal — never a whole-source `regenerate` — so it can't silently bless neighboring unreviewed lines, and it refuses server-side if the line already declares a target the current rendering doesn't match. It's shown only for an unaccounted line or a mismatch with no declared target; deliberately never exposed as an MCP tool, so an agent can prep a line but never approve its own fix. `line_status`/`line_status_for_text` now also carry `declared_target` so the extension can tell "no target declared yet" apart from "declared target not yet matched."
- Based on today's real `og`-pluriform-prefix session in `oldtupicorpus` (`docs/agent/session-handoffs/2026-09-16-og-pluriform-prefix.md`): its "What failed" note was that the long-running authoring MCP server kept the pre-edit grammar module cached, so `render_candidate` silently kept testing stale engine code until a fresh process was started — the main source of extra back-and-forth in that session. Added `authoring.service.reload_engine()` and a matching `reload_engine` MCP tool in the sibling repo (evicts cached `pydicate`/`tupi` modules so the next render reflects an on-disk `../nhe-enga` edit, without restarting the server) and wired it into the generated correction prompt as a required step after every engine edit.
- Restructured `buildCorrectionPrompt`'s steps around a single checkpoint: one human review (root-cause explanation + changelog preview) before any edit, then full autonomy through implementation, `reload_engine`, re-render, and a full cross-source regression check — the agent is told not to come back with a partially-passing state, and to hand a matching line back for a human "Commit ground truth" click rather than approving it itself.
- Sibling-repo changes: `authoring/service.py` (`commit_ground_truth`, `reload_engine`, `declared_target` field), `authoring/mcp_server.py` (registers `reload_engine` only — `commit_ground_truth` stays off the agent-facing tool list on purpose), `tests/commit_ground_truth_test.py` (new), `tests/mcp_server_test.py` (updated allowlist), plus `docs/agent/{current-state,log,source-authoring}.md`.
